# 旅言产品优化路线

本文档用于记录 MVP 当前阶段之后的产品优化方向。接下来按 1-5 逐项推进，每一项都应先保持范围克制，优先提升旅行现场翻译的核心体验。

## 1. 对话页语音状态体验升级

### 目标

让用户在旅行现场明确知道：当前是否正在听、听谁说、是否正在翻译、是否正在播放，以及失败后该怎么恢复。

### 优化内容

- 增加录音中的动态反馈，例如麦克风环形动效或轻量波形。
- 明确区分“听你说”和“听对方说”的状态。
- 将状态拆成更清楚的阶段：正在识别、正在翻译、正在播放、翻译失败。
- 识别过程中显示草稿气泡，避免用户误以为没有响应。
- 翻译失败时提供重试入口，而不是只显示错误文案。

### 验收标准

- 用户按下麦克风后，界面能立即反馈正在监听。
- 用户能看出当前监听的是“我说”还是“对方说”。
- 识别、翻译、播放三个阶段不会混在同一句状态文案里。
- 失败状态可恢复，至少支持重新翻译或重新录音。

## 2. 对话气泡信息结构优化

### 目标

让原文、译文、播放按钮和状态层级更清楚，使对话页更像真实翻译 App，而不是记录列表。

### 优化内容

- 原文和译文的字号、字重、颜色层级重新梳理。
- 播放按钮位置固定，避免长文本时漂移。
- 正在识别的草稿气泡使用浅色 loading 状态。
- 翻译失败的气泡显示失败状态和重试操作。
- 长文本换行和按钮间距需要在移动端保持稳定。

### 验收标准

- 一眼能区分原文和译文。
- 播放按钮在不同长度文本下都位置稳定。
- 草稿、成功、失败三类气泡状态清晰。
- 移动端无横向滚动和文字重叠。

## 3. 短句页升级为旅行场景助手

### 目标

让短句页从“静态短句库”变成旅行中不会说话时的备用方案。

### 优化内容

- 按旅行场景组织短句：交通、酒店、餐厅、购物、求助、医疗等。
- 点击短句后可以直接播放给对方。
- 可考虑将短句发送到对话页，形成一条可复用的对话记录。
- 增加最近使用短句。
- 后续可增加收藏短句，但 MVP 优先级低于最近使用。

### 验收标准

- 用户能快速按场景找到短句。
- 点击短句后的反馈明确，知道已经播放或已加入记录。
- 最近使用短句能帮助用户重复高频表达。

## 4. 历史页增加复用价值

### 目标

历史不只是存档，而是旅行中可以再次播放、复制、查找和复用的内容。

### 优化内容

- 历史详情中支持重新播放某一句译文。
- 支持复制整段历史，目前已有复制全文能力，可继续优化格式。
- 搜索结果中高亮命中的关键词。
- 历史详情消息流进一步贴近对话页气泡样式。
- 删除记录时可考虑二次确认，避免误删。

### 验收标准

- 用户能在历史中快速找到曾经说过的话。
- 用户能从历史中复用译文，例如复制或播放。
- 搜索命中位置清楚，不需要用户自己逐句找。

## 5. 设置页保持轻量但补齐信任信息

### 目标

设置页不做复杂配置，重点提供必要控制项和用户信任信息。

### 优化内容

- 保留默认源语言、默认目标语言、自动播放、播放速度。
- 增加清空历史入口，但需要谨慎设计确认流程。
- 增加隐私说明入口，说明语音、翻译和历史数据的处理方式。
- 后续可考虑音色、深色模式、离线偏好，但不进入当前优先级。

### 验收标准

- 设置项数量克制，没有压迫感。
- 用户能理解历史数据保存在本地还是会上传。
- 任何不可逆操作都有明确确认。

## 推荐推进顺序

1. 对话页语音状态体验升级。
2. 对话气泡信息结构优化。
3. 历史页复用能力。
4. 短句页旅行场景助手。
5. 设置页信任信息补齐。

优先做前两项，因为它们直接决定用户第一次使用麦克风时是否相信产品真的在工作。
